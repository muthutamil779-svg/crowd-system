Dual-Metric Risk Architecture

Traditional systems conflate pre-registration with live check-in. This platform divides crowd telemetry into two decoupled mathematical dimensions:

1. Pre-Event Risk Band (Demand Ratio) expectedAttendance / hallCapacity

Calculated prior to the event to flag overbooking early and allow organizers to expand venue seating before gates open.

2. Live Risk Band (Physical Occupancy) currentAttendance / hallCapacity

Evaluated in real-time as attendees scan in at the physical hall gate to dynamically detect fire-code hazards.

Sequential Check-In Guard Clauses

The checkInStudent(eventId, studentId) engine executes in strict numerical sequence to prevent state corruption:

Guard 1
Registration Verification: Checks if studentId exists in the event roster. Rejects immediately if unregistered.
Guard 2
Anti-Passback / Duplicate Guard: Checks if checkedIn === true. Rejects duplicate scans.
Guard 3
Capacity Threshold Guard: If currentAttendance >= hallCapacity, allows admission but returns overCapacityFlag = true to sound alerts without corrupting counters.
